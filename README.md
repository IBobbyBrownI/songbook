# Songbook

1. Как запустить с нуля
* Клонировать репозиторий: "git clone https://github.com/IBobbyBrownI/songbook.git"
* Скачать все библиотеки и компоненты: "composer install"
* Запустить локальный сервер: "php -S localhost:8000 -t public/"
* Открыть в браузере: localhost:8000



2. Архитектурные решения
* PHP: Для разработки, я выбрал PHP с Symfony-компонентами. Для полного понимания картины. С фреймворком было бы возможно быстрее, но к чему эта быстрота если запомнится лишь "Куда нажимать чтобы получилось что-нибудь". Для перспективы лучше использовать отдельные компоненты и понять как они работают. Мне понравилось какой пример привел AI. На моем этапе, работа с фреймворком будет похожа на микроволновку, положил еду, она разогрела вопросов нет, но готовить не научила. Какие есть приемущества при работе с компонентами: Во-первых это сокращает количество кода как например при использовании голого php; Во-вторых куча моментов, которые компоненты делают автоматически.
* DB: Для работы с БД, я выбрал MySQL. Для работы нашего приложения, необходима БД с возможностью создавать отношения М:М (Многие ко многим), MySQL проще для начального изучения, по-сравнению с PostgreSQL, хоть он и мощнее и возможно лучше, но в то же время она намного более функциональна чем SQLite, тем более для выхода в продакшен, испольщуя SQLite все-равно придется переезжать на MySQL либо другую Бдшку, поскольку SQLite блокирует всю базу целиком при записи. Если два пользователя одновременно добавляют песню, одному придется ждать другого, тут без шансов!
* Окружение: Тут без сомнений я выбрал Docker. Почему Docker а не Vangrant? Зачем для развёртования и запуска программы использовать ядро гостевой ОС, если можно использовать ядро своей ОС, и изолировать все процессы приложения. Это намного быстрее и занимает меньше мб, разница в минутах и гигабайтах, да и потом, тратятся ресурсы на поддержание ядра гостевого ОС. В Docker можно описать все что нужно приложеню в одном файле (Dockerfile либо Docker-compose), что позволяет спустя долгое время просто запустить проект и получить полностью идентичное окружение, какое было при разработке этого приложения. Почему не локальная установка? Самому всё поднимать, подключать и т.д.? А если нужно будет открыть проект на другом компьютере? Придется устанавливаться все необходимые для запуска компоненты. Поэтому этот вариант даже не рассматривается.
* Фронт: При работе с фронтом, выбор упал на Twig. Одно из требований, было исключить XSS (Межсайтовый скриптинг), Twig делает это автоматически. Касательно архитектуры приложения, Twig помогает избавиться от бесконечных include + Если где-то будет обнаружена ошибка, то Twig сразу скажет об этом, а не "сломанно" выдаст html.
* Транслит для Slug: В качетсве транслита для slug, мой выбор упал на cocur/slugify. Поскольку он просто берет строку и возвращает готовый slug с правилами аж для десятков языков. Не нужно писать кучу реплейсов, все уже готово. Казалось бы, есть еще вариант behat/transliterator, вроде тоже не плох, но такие вещи как пробелы, приведение к нижнему регистру, все пришлось бы делать самому, и вообще он создавался для других целей (чтобы превращать русские слова в английские для имен php-методов, а не для URL). Создавать всё в таблице выбор мазохиста xD.
